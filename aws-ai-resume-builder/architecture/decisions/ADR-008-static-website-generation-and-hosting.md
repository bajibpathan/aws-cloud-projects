# ADR-008: Static Website Generation and Hosting

## Status

Accepted

---

## Context

After Amazon Bedrock analyzes the uploaded resume, the application needs to generate a portfolio website that is easy to host, scalable, and inexpensive to maintain.

The generated website should:

- Be created automatically
- Be accessible through a web browser
- Scale without managing servers
- Have low hosting costs

---

## Decision

Generate the portfolio as a static website using HTML, CSS, and JavaScript.

Store the generated files in Amazon S3 and deliver them through Amazon CloudFront.

The website is generated by an AWS Lambda function using the structured JSON returned by Amazon Bedrock.

---

## Alternatives Considered

### Option 1 - Generate Static HTML (Chosen)

**Pros**

- Simple architecture
- Low hosting cost
- Fast page loading
- Easy to scale
- No web server required

**Cons**

- Limited server-side functionality

---

### Option 2 - Deploy a Dynamic Web Application

Examples:

- EC2
- ECS
- Elastic Beanstalk

**Pros**

- Supports dynamic features
- Full backend capabilities

**Cons**

- More infrastructure to manage
- Higher operational cost
- Unnecessary for this project

---

## Rationale

The generated portfolio is primarily static content that doesn't require server-side processing.

Using Amazon S3 and CloudFront provides a simple, scalable, and cost-effective solution while keeping the architecture fully serverless.

---

## Consequences

### Positive

- Low-cost hosting
- Automatic scaling
- Faster content delivery through CloudFront
- No server management
- Easy to update generated portfolios

### Negative

- Dynamic features require additional backend services
- CloudFront cache invalidation may be required after updates

---
